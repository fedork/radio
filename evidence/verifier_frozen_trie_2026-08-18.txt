Frozen solver-core negative refuter, 2026-08-18
================================================

Decision
--------

The independent kd-indexed verifier was stopped after its representative run9 gate had already
shown the relevant cost.  Run 20260818T062429Z verified 9,995/9,995 sampled k=7 four-part claims
with zero gaps in 3,197,377,218 recursion nodes and 341.32 wall seconds on 16 c8a.4xlarge vCPUs.
During the full phase it reached 251,131/2,576,885 k=7 claims (73,045 four-part), still with zero
gaps, after 2,160 seconds and 48,049,145,431 nodes.  It was then stopped deliberately: exit 130,
all final-manifest hashes checked, and instance i-0b81cd58d3ba14f0c terminated.  Repeating more
search than the original solver is not a useful verifier endpoint.

The replacement is radio_refute.c at commit
e0402900f4a74853ac44344aa8080c41ce0688fe.  It deliberately shares the production solver core;
it is a validation replay, not an independent implementation.  The intended comparison is the
user-proposed baseline: perform the same exhaustive refutation as the solver, but against a
read-only cache and without recursive solving or learning.

Frozen-epoch contract
---------------------

1. Parse the readable radio-negative-certificate-v1 envelope and load all negative facts into the
   production compact dominance trie once.  No binary certificate format is needed.
2. Before workers start, materialize every root-part split table required by the selected batch and
   advance its one-part s[4]/s[5] viability frontier using theorem checks and CACHE_ONLY queries.
3. Publish a read epoch.  Each worker owns radio_search_context (accepted-prefix clock, exact L1,
   and reachability workspace).  A queried level-k root bypasses its own L1/external/trie entry,
   starts at exhaustive pass 2, and never writes the cache or split metadata.
4. Every child is at k-1 and is answered only by an exact theorem or the immutable negative trie.
   One FALSE child rejects the test.  A complete split with no FALSE child is reported as a gap;
   it is never recursively solved.  Therefore worker order and cross-level barriers are irrelevant.
5. Cache arena allocation counts and a checksum of every materialized split table are compared
   before and after the worker epoch.  Any mutation is fatal.  Per-root reachability diagnostics
   are suppressed in this mode; batch progress reports completed claims, per-level totals, prefix
   throughput, ETA, and the three longest-running active roots.

Post-run optimization profile
-----------------------------

Parallel scheduling is not the limiting factor.  The dominant epoch's CPU/wall ratio is 15.985
on sixteen workers, as are the lower and upper epochs to three decimal places.  Per-root atomic
dispatch, the progress thread and load balance therefore have little useful headroom; a language
rewrite or finer locking would not reduce the measured CPU work.

A current-HEAD `-O3 -g -fno-omit-frame-pointer` Sa(113) control replayed the complete 304,105-claim
normalized corpus on twelve M4 Pro workers.  It closed with zero gaps in 1,272,552,775 prefixes,
11.517 wall / 119.222 CPU seconds.  An eight-second, 1-ms `sample` window covered 73,224 runnable
worker samples.  The collapsed top-of-stack counts were:

  canSolveB_ctx                              44,535  (60.8%)
  star_expansion_majorization_can_solve      25,425  (34.7%)
  other running frames                         3,264   (4.5%)

The theorem cost is actionable.  A CACHE_ONLY child currently probes its worker L1, then—on a
miss—runs full-star majorization before the immutable negative trie.  During a frozen epoch a trie
negative is already a sufficient lower-level citation, so the first controlled variant should use
L1 -> explicit-exact/trie -> theorem fallback.  Do not change ordinary solver ordering with it.
Add per-worker counters first: L1 queries/hits/collisions, exact-fact hits, dominance hits, theorem
hits and misses.  A flat read-only exact hash of the 3.126 million explicit claims is likely the
best limited denormalization experiment; it avoids eagerly materializing the full implied closure.
Also test a larger or two-way worker L1 only after its hit distribution is known.  The proposed
read-only order `(k, part count, total pair mass, each part's pair mass, long side)` is a credible
structure-of-arrays range index; benchmark it against a simple contiguous flattening of the current
trie rather than assuming the extra keys win.

The next search-work experiment is aggregate reachability telemetry: roots armed, build time,
tests and prunes by part count.  Tune RB_TRIGGER on the retained 9,995-root four-part gate rather
than inheriting the solver's ten-million-prefix threshold blindly.  This can reduce the 3.437
trillion dominant prefixes; cache micro-optimizations cannot.

Pre-verification minimalization is sound and easy but bounded in value.  The established k=7
antichain has 2,507,270 facts versus 2,576,885 inputs, only 69,615 (2.702%) fewer; all-level cache
loading marked 275,570 of 3,126,190 insertions redundant.  Record redundant claims as theorem-
derived from verified minima instead of re-enumerating them, but do not expect this alone to move
the dominant runtime materially.

Three process launches spent 878.207 seconds rebuilding the same trie.  A single process with
separately checkpointed batches would save about ten minutes immediately.  A contiguous,
serializable derived cache/split image would make repeated benchmarks and distributed shards start
cheaply and improve locality while keeping the readable certificate authoritative.  Distributed
root shards are otherwise straightforward and spot-friendly, but they reduce latency rather than
aggregate CPU.  The asymptotically stronger independent verifier remains an explicit split-space
cover whose ranges cite lower-level facts; it should not re-enumerate trillions of prefixes.
