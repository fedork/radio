# Deadline investigation, final correction: bounded breadth with a short constructive spine

Status: measured engine diagnosis and performance evidence, 2026-08-11.  The retained raw logs are
in the private artifact tags `bounded-probe-2026-08-11` and
`bounded-probe-rejected-2026-08-11`; every archived log passes the strict embedded-provenance check.

Scheduler update, 2026-08-13: the shared-bound and geometric-deepening state machine below remains
current, but new builds measure its allowance in deterministic accepted split prefixes rather than
process CPU time.  References below to CPU-second slices and 65,536-prefix polling describe commit
`45c34fd` and the frozen Sa(193) runs.  Calibration, new regression coverage, and the CPU fallback
are in [`work_budget_rb_root_2026-08-13.txt`](work_budget_rb_root_2026-08-13.txt).

## Why this file changed twice

The original 2026-08-10 account called the long run4/run5 child a deadline livelock.  The first
2026-08-11 correction retracted that claim after source history showed the behaviour was deliberate:
a bounded call had to add a negative cache fact before returning `MAYBE`, and exhaustive pass 2 gave
an unresolved child `NO_DEADLINE`.  That correction was right about what the old code *intended* but
wrong to conclude that the intention was safe.

Run7 supplied the missing evidence.  After 5 h 40 m it was still inside the same information-tight
state, now after 270,697,771,548 admitted prefixes:

```
Sb(9:4,8:4,8:1,5:5,15:1,5:3,6:3,7:2,5:3,11:1,8:2,11:1,14:1,13:1)@5
```

Its pair mass is exactly `243 = 3^5`.  The k=5 call was in exhaustive pass 2 beneath a finite
parent, but the old pass-2 rule had converted the child to `NO_DEADLINE`.  The global negative count
remained one below the caller's required minimum.  With a saturated cache, zero new negative facts
is normal; tying cancellation to such a mutation therefore removes the finite escape exactly when
it is most needed.  A read-only status snapshot at 2026-08-11 21:26 UTC recorded 19,859 CPU seconds
in this activation and no completed `Sa(192)` control.

The run was deliberately stopped at 2026-08-11 22:13:30 UTC. Its final snapshot recorded 20,460 CPU
seconds and 280,116,882,707 admitted prefixes in the same activation, 104,931 definitive internal
verdicts, and still no completed control. The finalized raw segment has 104,936 lines and SHA-256
`a79d31d9b11bf97679451087b90978f7fdc3b8874847bda2ebca305142ddb72c`; the finalized checkpoint
has SHA-256 `b7e63923275caa4d486fbefd5cd912cf80d8a530c36372fbf14cece2b8cae545`. Both are under the
private `run7/` S3 prefix together with the exact source archive, frozen binary and launch metadata.

The earlier debugger observations remain valid historical evidence: run4/run5 reached the same
state, and commit `c13b5d3`'s prefix poll could return before any complete child was tried.  What is
superseded is the proposed cure.  Neither an unconditional pass-2 dive nor a zero-budget prefix
retry is a usable scheduler.

## Implemented state machine (`45c34fd`, historical CPU-clock incarnation)

The replacement keeps no split cursor, score or remembered winning split.

* An expired finite parent stays expired.  A descendant never receives a fresh minimum interval.
* A finite call may return `MAYBE` with zero cache mutations.  `FALSE` is still printed/cached only
  after an unskipped exhaustive pass, so this cannot manufacture a negative.
* One- and two-segment states keep their caller's shared absolute allowance.  This preserves the
  observed constructive spine: the ratio-preserving first cut and the opposed-branch two-segment
  cut can compose into the first genuinely long state.
* States with at least three segments give each speculative child an initial two-CPU-second slice.
  All still-possible siblings are checked unless one is already `FALSE`.
* After an unresolved exhaustive pass, the local slice doubles.  Thus even a saturated cache changes
  the allowed work on the next pass; pure same-budget spinning is impossible without storing which
  split happened to look promising.
* Finite prefix enumeration polls the shared deadline every 65,536 admitted prefixes.  This is safe
  under the new policy because there is no later `NO_DEADLINE` handoff to bypass.

`tools/deadline_regression.c` checks exhausted-parent inheritance, long-state division, the shared
one/two-segment cap, the local quantum, and immediate `MAYBE` on an expired cache miss.

## Focused validation

The exact saturated k=5 state above was replayed against the run7-derived checkpoint with a
one-second finite parent.  It returned `MAYBE` in 1.000 CPU second with
`negative_delta=0`.  This is the case the old progress gate could not escape.  Source:
`bounded-probe-2026-08-11:finite-k5-final.out`, build ID
`8ae1c2b6881db63ab04254cb74df55e19140158fb99c35084c257431c03acc18`.

Against the same checkpoint, the intended positive path composed without a stored hint:

```
Sb(33:16,32:15,23:19,45:9)@7
  [17:8,27:13,10:8,12:0]                         22.0 CPU s
Sb(48:48,64:32)@8
  [16:15,45:23] -> the k=7 state above             22.0 CPU s
Sb(112:80)@9
  [48:32] -> the k=8 state above                   22.0 CPU s
```

The second split is the symmetric form of `[33:32,19:9]`; the first cut is the symmetric form of
`[64:48]`.  Sources: `bounded-probe-2026-08-11:k7-structural.out`,
`k8-structural.out`, and `k9-structural.out`, all build ID
`e07be334856587114ef51522567bca93629fe623637df78bc422f6b7a244885b`.

Most importantly, a genuinely cold normal-learning control completed:

```
Sb(112:80)@9  SOLVABLE in 281 CPU s, 446 admitted top-level candidates
Sa(192)@10    SOLVABLE in 376.293 CPU s
```

The wrapper measured 382 s wall and 0.18 GiB peak RSS.  The emitted path is exactly the three lines
above.  Source: `bounded-probe-2026-08-11:sa192-structural-final-cold.out`, build ID
`5d3887defae285963a00671c91e0f78a4487e61478f0c9cfbfd3c6a75529e94f`.
That validation build embeds every dependency hash; commit `45c34fd` adds only probe-state reporting
after the measured search-semantic source.

The optimized regression corpus emitted the same 1,038 definitive one/two-part answers as prior
main, and the ASan+UBSan build matched them with no diagnostics.  The normalized output SHA-256 is
`2cf020540919d6fe2f8da20636ecceb8f8d14ccc4d5a3cd599ac0a91e99eade2`.

## Rejected simpler variants

These failures are part of the result, not future suggestions:

* A universal two-second child slice fixed the k=7 state but starved its enclosing k=8 state.  The
  k=8 replay was still in its first pass after the 360-second cap, at 1,319 admitted candidates and
  `left=794/1149`; peak RSS was 0.53 GiB.  Source:
  `bounded-probe-rejected-2026-08-11:k8-iterative.out`.
* The same universal slice in a cold `Sa(192)` control eventually entered root pass 2 and again
  handed candidate 5 an unbounded child.  It was stopped after 16 m 20 s rather than rediscover the
  old sink.  Source: `bounded-probe-rejected-2026-08-11:sa192-core-cold.out` and its retained local
  stack sample.
* Immediately committing 30 or 40 seconds to a candidate after two easy children were `TRUE`
  advanced only about seven k=8 candidates per minute; bad near-candidates consumed the whole
  allowance.  Repeating fixed two-second passes based on cache growth also failed because both the
  good and bad long states kept generating facts while restarting from the same prefix.
* Persisting a winning split/cursor was deliberately not implemented.  Besides storage complexity,
  it would over-credit a solution that may only reflect the current probe order.

## Run disposition

Run6 remains a broken zero-progress/prefix-poll experiment; its printed definitive verdicts are
sound, but its timing is not a comparison baseline. Run7 is retained diagnostic evidence for the
opposite failure and was stopped only after its raw log, checkpoint, profile, source and launch
metadata were archived and verified. Run3 remains the live incumbent and was unaffected. Do not use
a missing line from any interrupted sidecar as a negative verdict.
